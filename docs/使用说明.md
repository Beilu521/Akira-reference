# Akira 使用说明

> 面向使用者的完整手册:获取程序 → 初始化 → 日常使用 → 部署常驻 → 故障排查。
> 设计与学习向内容见 [README](../README.md) / [复现指南](复现指南.md) / [架构演进](架构演进.md)。

## 一、获取程序(三选一)

**方式 A:下载现成二进制(推荐)**
打开项目 GitHub 页 → Releases → 按平台下载:
| 文件 | 平台 |
|---|---|
| `akira-windows-amd64.exe` | Windows |
| `akira-linux-amd64` | Linux |
| `akira-darwin-arm64` | macOS(Apple Silicon) |

下载后(Linux/macOS)`chmod +x akira-*` 即可运行。打 tag 会自动构建发布(CI 已配置)。

**方式 B:源码构建**
```bash
git clone <仓库地址> && cd akira-reference
make build        # 产物在 bin/akira
make release      # 一键产出三平台到 dist/
```

**方式 C:Docker**
```bash
docker build -t akira .
docker run --rm -v /var/log:/logs akira watch /logs/app.log
```

> 说明:Go 的分发形式就是单个静态二进制,没有 node_modules/运行时依赖,
> 不需要 npm 这类包管理器——拷走一个文件就是完整安装。

## 二、第一次使用(3 分钟)

```bash
# 1. 交互式初始化:问答式填好配置,自动连通性测试,写 configs/config.yaml
akira init
# 会依次询问:LLM 地址 → API Key → 模型名(回车用默认值)

# 2. 看双层闭环演示(内置假日志,验证安装是否成功)
akira demo

# 3. 常驻监控你的第一个日志文件
akira watch app.log            # 文本模式
akira watch app.log --tui      # 仪表盘模式(推荐)
```

**多文件监控**:
```bash
akira watch /var/log/nginx/access.log /var/log/app.log "logs/*.log"
```
每个文件独立维护行号(取证时 read_log_context 对应各自文件),告警标注来源文件。

**环境变量(可选)**:以下变量优先于 config.yaml,容器/CI 场景不用改文件:
| 变量 | 作用 |
|---|---|
| `AKIRA_BASE_URL` | 覆盖 LLM 地址 |
| `AKIRA_API_KEY` | 覆盖 API Key |
| `AKIRA_MODEL` | 覆盖模型名 |

**没有 API Key?** 加 `--mock` 体验完整流程(内置假 LLM,离线零成本):
```bash
akira --mock demo
akira --mock watch app.log --tui
```

## 三、命令参考

| 命令 | 作用 | 常用参数 |
|---|---|---|
| `akira init` | 交互式初始化配置 + 连通性测试 | `--force` 覆盖已有配置 |
| `akira demo` | 双层闭环演示(内置假日志) | — |
| `akira watch <文件...>` | 常驻监控:tail 多文件(支持 `*.log` 通配符)→ 检测 → 告警 → Agent 分析 | `--tui` 仪表盘;`--from-start` 从头读 |
| `akira analyze <文件>` | 一次性分析:异常汇总 + 根因报告 | `--from/--to` 时间区间;`--out 报告.md` 落盘 |
| `akira history` | 查看历史告警(SQLite) | `-n 20` 条数 |
| `akira eval` | 规则评测:精确率/召回率/F1 | `--cases` 自定义集;`--scale 100000` 大规模 |
| `akira serve` | HTTP 服务:REST API + /metrics | `--addr :8080` |
| `akira version` | 版本信息 | — |

**全局参数**(放在子命令前):`--config 路径` 指定配置;`--verbose` debug 日志;`--mock` 离线假 LLM。

```bash
# 组合示例
akira --config prod.yaml watch /var/log/app.log --tui
akira analyze app.log --from "2026-08-28 10:00:00" --to "2026-08-28 12:00:00" --out report.md
akira eval --scale 100000        # 10 万行评测:准确率 + 吞吐
```

## 四、TUI 仪表盘(`watch --tui`)

```
● Akira 监控中   app.log · 模型 xxx · 运行 5m32s
日志行 12,345   命中 56   告警 12   分析 10✓/1✗   tokens 8,900
吞吐 ▃▅▇▅▃▁▂ 1,240 行/秒
╭─ 规则命中 ──────────────────────────────╮
│ docker_oom    ████████████████ 32      │
│ nginx_5xx     █████ 12                 │
╰────────────────────────────────────────╯
╭─ 最近告警 ──────────────────────────────╮
│ 12:00:01 ● critical docker_oom ...     │
╰────────────────────────────────────────╯
 q 退出
```

- **面板含义**:命中条形按次数归一;告警圆点按级别配色(红=critical/橙=warning/青=info);`×N` 表示聚合窗口内合并的次数;`⟳` 表示正在做深度分析
- **按键**:`q` 或 `Ctrl+C` 退出(走优雅关停,在途分析完成后再退)
- **刷新**:500ms;关键事件(新告警/分析完成)立即刷新
- 建议用 Windows Terminal / iTM2 等现代终端,色彩和边框渲染最佳

## 五、配置参考(config.yaml)

| 段 | 字段 | 说明(默认值) |
|---|---|---|
| llm | base_url / api_key / model | OpenAI 兼容地址、密钥、模型名 |
| llm | temperature / max_tokens | 温度 0.2;单次最大 token 2000 |
| llm | timeout_seconds / max_retries | 单请求超时 60s;失败重试 1 次(仅 5xx/429/网络错误) |
| agent | max_iterations / timeout | ReAct 循环上限 10;单次分析整体超时 300s |
| watcher | poll_interval_ms | 日志轮询间隔 500ms |
| detector | rules[] | 规则:id / pattern(正则) / component / severity / suggestion |
| alert | cooldown_seconds | 同规则告警冷却 300s |
| alert | aggregate_window_seconds | >0 开启滑动窗口聚合(同规则窗口内合并成 1 条告警) |
| alert | wecom / feishu(+secret) / webhook | 告警渠道,配了即启用,可多渠道并存 |
| storage | enabled / path | SQLite 存档 alerts.db |
| knowledge | auto_save / embedding_model | 自动复盘入库;向量模型(配了启用混合检索) |
| metrics | addr | /metrics 端点(如 :2112),空 = 关闭 |

**规则怎么写**:pattern 是 Go 正则;component 是归因; suggestion 会作为上下文喂给 Agent。
改规则前跑 `akira eval` 存个数字,改完再跑对比——防止修一条规则的误报弄坏另一条。

## 六、知识库(进化闭环)

分析成功后自动提炼"复盘卡片"入库(签名去重:同类故障只累加复用次数);再遇相似问题,
检索 top-k 注入 Agent 的 prompt,Agent 直接复用历史结论。配 `embedding_model` 后升级为
"TF-IDF + 向量"混合检索(RRF 融合)。查看:`akira history`;Agent 也可用
`save_knowledge` / `search_knowledge` 工具主动沉淀与检索。

## 七、HTTP API(`akira serve --addr :8080`)

```bash
curl localhost:8080/healthz                                    # 探活
curl "localhost:8080/api/alerts?limit=10"                      # 最近告警(JSON)
curl -X POST localhost:8080/api/analyze \
     -d '{"path":"app.log"}'                                   # 规则扫描
curl -X POST localhost:8080/api/analyze \
     -d '{"path":"app.log","deep":true}'                       # + Agent 深度分析
curl localhost:8080/metrics                                    # Prometheus 指标
```

**鉴权**:config 里配 `server.token: "你的令牌"`(或环境变量 `AKIRA_SERVE_TOKEN`)后,
`/api/*` 需要 `Authorization: Bearer 你的令牌` 或 `X-Auth-Token` 头;`/healthz` 与 `/metrics` 仍公开。

## 八、MCP 接入(让 Claude Desktop 直接用你的日志工具)

`akira mcp` 以 stdio 方式运行 MCP(Model Context Protocol)服务器,把 8 个工具
(日志上下文/搜索/异常扫描/知识库检索与沉淀等)暴露给任意 MCP 客户端。

**Claude Desktop 配置**(claude_desktop_config.json):
```json
{
  "mcpServers": {
    "akira": {
      "command": "C:\path\akira.exe",
      "args": ["mcp"],
      "env": {"AKIRA_API_KEY": "sk-xxx"}
    }
  }
}
```
重启 Claude Desktop 后,即可直接对话式调用:"帮我看看 app.log 第 100 行附近有没有异常"、
"在经验库里找找类似的 OOM 故障"。

说明:
- 协议为 JSON-RPC 2.0 over stdio,**标准库手写实现**,不依赖任何 SDK(internal/mcp)
- 同一套工具,三种入口:ReAct Agent(自动编排)/ HTTP API / MCP 标准协议
- 安全:工具白名单只含日志取证与知识库读写;不含通用文件系统工具(最小权限)
- 鉴权复用 serve 的 `server.token` / 环境变量配置

## 九、常驻部署

**Linux(systemd)** `/etc/systemd/system/akira.service`:
```ini
[Unit]
Description=Akira log agent
After=network.target

[Service]
WorkingDirectory=/opt/akira
ExecStart=/opt/akira/akira watch /var/log/app.log
Restart=on-failure
Environment=AKIRA_API_KEY=sk-xxx

[Install]
WantedBy=multi-user.target
```
`systemctl enable --now akira`

**Windows**:任务计划程序 → 开机运行 `akira.exe watch C:\logs\app.log`;
或用 nssm 包装成 Windows 服务。

**Docker**:见 Dockerfile;日志目录以 `-v` 挂载进容器。

## 十、故障排查

| 现象 | 原因与处理 |
|---|---|
| 连通性测试 401/模型不存在 | 检查 api_key / model 拼写;`akira init --force` 重填 |
| 分析一直超时 | 调大 `llm.timeout_seconds`;或网络不通先用 `--mock` |
| watch 看不到告警 | 确认写入的行能命中规则(拿该行去 `eval` 样本里试);确认没在冷却/聚合窗口内 |
| analyze 时间过滤无效 | 日志行需要 `YYYY-MM-DD HH:MM:SS` 时间前缀 |
| TUI 边框乱码 | 用 Windows Terminal / 现代终端;降低终端缩放 |
| alerts.db 在哪 | 运行命令时的工作目录(config 的 storage.path) |
| 想零成本体验 | `--mock` 全流程离线;`eval`/`history` 本身不调 LLM |

## 十一、卸载

删除三样即可:二进制文件、`configs/config.yaml`(含你的 Key)、`alerts.db`(历史存档)。
